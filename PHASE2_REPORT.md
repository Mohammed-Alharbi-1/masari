## 4. طريقة تنظيم البيانات

يعرّف TypeScript عقود Certification وCertificationProvider وCareerTrackInfo، مع قيم محددة للمستوى ونوع المؤهل وحالة الإتاحة والتحقق. أُتيح unknown للمستوى والحالة، وnull للحقول غير المؤكدة. يشير كل سجل إلى providerId موجود وإلى معرّفات المجالات المركزية. أُضيف notesAr للتنبيهات المهمة، وsourceDomains للجهات لرفض المصادر الواقعة خارج نطاقاتها المعتمدة.

الأسماء والأنواع والمجالات والمستويات وحالات التحقق التي تعرضها البطاقات تأتي من الملفات المحلية. تقرأ الرئيسية تعريف المجالات نفسه؛ بقيت الألوان والأيقونات عرضًا بصريًا منفصلًا. لا توجد قاعدة بيانات أو طلبات API للكتالوج أو localStorage.

لإضافة شهادة، افتح المصدر الرسمي وتحقق من البيانات، ثم أضف سجلًا بمعرّف ثابت وعلاقات صحيحة. أضف الجهة أولًا إذا كانت جديدة. ضع pending وتاريخًا فارغًا عند عدم المراجعة، وunknown عند الشك في الإتاحة أو التصنيف. ميّز توصيات الاستعداد عن الشروط الإلزامية، ولا تستنتج سعرًا من مصدر لا يحدد السياق المحلي. أعد فحص الرابط والمحتوى والتاريخ عند كل تحديث ثم شغّل validate:catalog وlint وtypecheck وbuild. التعليمات العملية في README.

## 5. واجهة الشهادات

تحتوي الصفحة العنوان والوصف المطلوبين، وملخصًا محسوبًا من البيانات، ثم شبكة بطاقات تعرض الاسم الرسمي والجهة والمجالات والمستوى الإرشادي والنوع والوصف وحالة الإتاحة والتحقق وتاريخ المراجعة. تعرض بطاقة AWS Developer تنبيه إصدار الاختبار. تحمل الروابط target="_blank" وrel="noopener noreferrer" مع إشارة لقارئ الشاشة بأن الرابط يفتح تبويبًا جديدًا.

يوضح قسم ختامي الفرق بين الشهادة الاحترافية وشهادة إتمام الدورة والشارة الرقمية، وعدم تكافؤها. الأنواع الموجودة حاليًا تُستخرج من السجلات. لا تُعرض الأسعار الفارغة كصفر أو كاختبارات مجانية. لم تُضف نماذج أو بحث أو تصفية أو فرز تفاعلي أو مقارنة أو توصيات.

تعتمد الصفحة ألوان مساري وخطها وترويسّتها وتذييلها وRTL. الشبكة عمود واحد للجوال، وعمودان للأحجام المتوسطة، وثلاثة لسطح المكتب. البطاقات الطويلة تلتف دون تمرير أفقي، والروابط الرسمية لها مساحة تفاعل بارتفاع 44 بكسل على الأقل.

الأثمان والعملات كلها null. ظهرت أسعار عامة في بعض الصفحات، لكن لم يُتحقق من عرض تكلفة سعودية شاملة؛ لم تُضف تحويلات أو ادعاءات بمجانية الاختبار أو دعم هدف أو تعويض مالي. المستوى مبتدئ يطابق Beginner أو Foundational أو Entry في هذه المصادر، والمتوسط يستند إلى Intermediate أو Associate وخبرة المرشح، ويظهر كتقدير إرشادي في مساري.

المرحلة الثانية مكتملة تقنيًا وجاهزة للمراجعة: بيانات منفصلة ومراجعة، صفحة قراءة فعلية، اختبارات ناجحة، وتوثيق للصيانة وحدود المعلومات. تسليم GitHub يُستكمل بعد هذا التقرير وتُسجل نتيجته في الرد النهائي.

على المراجع مراجعة ملاءمة إسناد شهادات أدوات التطوير إلى الويب، وتصنيف Associate ضمن المستوى المتوسط، وتنبيه AWS Developer، وسياسة مراجعة المصادر والأسعار قبل الترخيص بالاستبيان. لا توجد توصية شخصية في الكتالوج، ولم يبدأ تنفيذ المرحلة الثالثة.

تم الانتهاء من المرحلة الثانية، والمشروع جاهز للمراجعة قبل الانتقال إلى المرحلة الثالثة.
